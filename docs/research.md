# 先行調査（2026-11-06 実施）

文字数カウント系サイト10件と、関連 OSS の調査記録。**確度はいずれも「中」**（公開されている HTML / JS 断片からの推定で、サーバー側の処理や実機での厳密な挙動は確認していない）。
既存サイトのコード・文言・デザインは複製しない。ここに書くのは「何が弱点・良い点か」の整理だけ。

## 結論

- 共通の弱点: 広告・説明が入力欄より前、または数値と入力欄の間に入る／ボタンを押して初めて数える式（wingarc）／集計方式の不明示／`length`（UTF-16）で絵文字を2字と数える（gacco ほか）／CRLF 未正規化・漢字範囲が狭い（schit）。
- 良い点の参考: adregion（Intl.Segmenter と改行正規化、広告なし）、robse（「UTF-16単位」と方式を明記、÷400 と並べた枚数、保存は初期オフ）、sundryst（原稿用紙の禁則考慮）、shin-yu（UTF-8 バイトを正確に）。
- 方針: **Intl.Segmenter（書記素）を標準機能のまま採用し、ライブラリを足さない**。方式を画面に明記し、入力欄と数値を最上部に置き、ボタンなしで即時に数える。

## 原稿用紙換算の流儀

3通りある: ①文字数÷400、②20字で折り返した行数÷20、③禁則・ぶら下げ込み。本ツールは①と②を併記し、③は拡張候補とした。

## 字種・絵文字の方針

- 長音「ー」は `Script=Common` なので、明示的にカタカナへ含める。「々」「〆」「ヶ」は Node で実測して固定した（counting-spec.md）。
- 絵文字は v フラグの `\p{RGI_Emoji}` を書記素全体に当てる。非対応環境は `\p{Extended_Pictographic}` で代替。

## 今後の拡張候補

原稿用紙の禁則対応、East Asian Width 表の内蔵、Shift_JIS バイト数、PWA／オフライン、文字数の目標別プリセット、本文の差分表示（2文比較の発展）。第2段階（2文比較・履歴）は見送り（理由は DESIGN.md）。拡張候補として「基準との差」（数値のみをメモリに保持し、校正前後の字数差を表示）を追加。
